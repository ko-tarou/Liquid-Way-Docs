## 5. LFM モデル群（調査結果）

| モデル | 特徴 |
|---|---|
| **LFM2.5-350M** | 最小エッジモデル。プロンプトだけで実用的なコード生成が可能。ko-tarou が Python Socket.IO の早押しクイズで実機確認し、驚くほど良好だったとのこと |
| **LFM2.5-1.2B-JP** | 日本語特化。JMMLU / M-IFEval(ja) / GSM8K(ja) で同サイズ帯トップ。<1GB でスマホ動作（70〜82 t/s） |
| **LFM2.5-1.2B-Thinking** | 推論特化 |
| **LFM2.5-VL-450M / 1.6B** | 512×512 ネイティブ。日本語対応 |
| **LFM2.5-Audio-1.5B** | 英語のみ E2E speech |
| **LFM2.5-Audio-JP** | 近日公開、仕様未公開（**賭けポイント**） |

### 共通仕様

- ライセンス: LFM Open License v1.0（**商用利用可**）
- フォーマット: GGUF / ONNX / MLX / Transformers
- LEAP SDK: Kotlin Multiplatform、Android は本番 Ready、iOS は testing
- 公式テストアプリ: Liquid Apollo

## 6. AMD Ryzen AI PC スペック（提供ハード予想）

| 機種 | NPU | メモリ | 電源 |
|---|---|---|---|
| AMD NUC（Ryzen AI 9 HX 370） | 50 TOPS | 64GB | **100V コンセント** |
| Framework Desktop（AI Max+ 395 Strix Halo） | 50 TOPS | **128GB 統合メモリ** | **100V コンセント** |

### ⚠️ 事前認識の補正

| 項目 | 事前認識 | 実際 |
|---|---|---|
| 電源 | Ryzen AI PC は 200V 極太ケーブルが必要 | **誤り**。通常の 100V コンセントで動作 |

### 実測スループット参考値

| モデル | 実測 | 条件 |
|---|---|---|
| LFM2-1.2B | 63 tok/s | NPU |
| LFM2.5-1.2B-Thinking | 52 t/s @16K | NPU + FastFlowLM |
| LFM2.5-1.2B | 239 t/s decode | CPU on Max+ 395 |

### ランタイム / SDK

- **Lemonade SDK**: OpenAI 互換 API `http://localhost:13305/api/v1` → 既存の ChatGPT 連携アプリのコードを流用可能
- **FastFlowLM**: NPU 特化ランタイム。32K context 維持

### スマホ ↔ PC 構成の目安

- LFM2-1.2B で **同時 3〜5 人** のリアルタイム会話が可能
- **10 人規模**なら非同期構成が現実的

## 7. 戦略の補正（重要）

公式テーマの北極星は「**パラメータあたりの性能と計算メモリの効率を活かしてほしい**」です。これを踏まえ、当初仮説を以下のように補正しました。

| 観点 | 当初仮説 | 補正後 |
|---|---|---|
| Fine-tune の位置づけ | 事実上必須 | **強化手段の一つに過ぎず、絶対条件ではない**。350M がプロンプトだけで実用レベル |
| 勝ち筋 | オンプレ 3 軸（コスト / 機密 / オフライン） | コスト軸は弱い。**「小ささ・速さ・マルチモーダル統合」を直接見せる**のが北極星 |
| 機能設計 | 単体機能で勝負 | **マルチモーダル統合（Text + VL + Audio-JP）が穴**で差別化可能 |
