# LiqMesh Distributed Systems ADR

Status: Proposal

Source Date: 2026-05-12

Updated: 2026-05-22

この文書は LiqMesh の分散システム設計だけを扱う。UI、応募資料、モデル比較、デモ演出は対象外とする。

## Scope

- 端末間通信
- ネットワークトポロジ
- サーバー役の選定ルール
- オフライン蓄積と再同期
- 重複排除
- 障害時の復旧

## Context

災害時の通信断絶を前提に、端末同士で情報共有を継続する。インターネットやクラウド常時接続は前提にしない。

## 技術

| 領域 | 技術 | 役割 |
|---|---|---|
| 近距離通信 | Wi-Fi Direct / BLE / 共有 AP | 端末接続とメッセージ転送経路の確立 |
| トポロジ | P2P メッシュ（MVP はスター簡略可） | 端末間の情報流通 |
| 役割管理 | 充電中端末のみ候補にした動的選出 | 非充電端末の消耗を避けつつ役割を自動更新 |
| 永続化 | 端末内 DB | 切断時の蓄積、再接続後の同期 |
| 同期 | メッセージ ID ベース差分同期 | at-least-once 配送下の冪等化 |

## Decisions

### 1. 通信はオフライン前提の端末間接続に限定する

- 通信は Wi-Fi Direct / BLE / 共有 AP のいずれかで構成する。
- インターネット到達可否に依存しない。
- クラウド経由は中核経路にしない。

### 2. サーバー役は「充電中端末のみ候補」の動的選出にする

- サーバー候補は充電中端末に限定する。
- 候補集合（充電中端末）内では、自動昇格・自動再選出を許可する。
- 非充電端末は通常時の候補に含めない。
- 充電端末が 0 台の間はサーバー不在運用とし、リーフ同士の蓄積を継続する。
- 充電端末が復帰した時点でサーバー役を再選出し、差分同期を再開する。

### 3. 配送は at-least-once、受信側で重複排除する

- 各メッセージに一意 ID を付与する。
- 送信失敗時はローカルに保持し、再接続後に再送する。
- 受信側はメッセージ ID で冪等に重複を除外する。

### 4. 端末ごとのローカル蓄積と差分同期を前提にする

- 投稿はまずローカル DB に保存する。
- 接続回復時に未共有分だけ差分同期する。
- 編集・削除・厳密順序より、追記型共有を優先する。

### 5. 障害復旧は充電候補内の自動再選出で復旧する

- サーバー端末が離脱した場合は、残っている充電中端末から自動で再選出する。
- 充電端末が 0 台の間はサーバー不在で蓄積のみ継続する。
- 充電端末が復帰したら自動再選出し、復旧後に差分同期する。

## Alternatives Considered

- 全端末対象の動的サーバー選出: 非充電端末の消耗が大きいため不採用。
- 固定単一サーバー前提: 端末離脱時の継続性が弱いため不採用。
- クラウド中継前提: 災害時要件に合わないため不採用。

## Open Questions

- MVP で Wi-Fi Direct と BLE のどちらを主経路にするか。
- スター簡略とメッシュ中継の切替条件をどう定義するか。
- 充電中端末が複数ある場合の自動選出スコア式をどう定義するか。
