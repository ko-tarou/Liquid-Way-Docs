# LiqMesh 分散システム要件サマリ

Date: 2026-05-26

| 項目 | 内容 |
|---|---|
| 対象範囲 | ノード間通信、トポロジ、サーバー役選定、配送保証、永続化、再同期、障害復旧 |
| 前提環境 | 災害時の断続接続・分断・再接続を前提とし、中央クラウドなしで継続動作する |
| トポロジ | 論理メッシュを基本とし、初期実装ではスター簡略構成を許容。同期プロトコルはトポロジ非依存 |
| サーバー役選定 | 充電中ノードのみ候補。候補から手動で1台選定。充電中ノード不在時はサーバー不在モード |
| 配送保証 | at-least-once。各メッセージに一意IDを付与し、受信側で冪等化して重複排除 |
| 永続化と再同期 | 送信前ローカル永続化、失敗メッセージは再送キュー保持、再接続時にhigh-water mark差分同期 |
| 障害復旧 | 不在中は各ノードが蓄積継続。再確立後に同期再開 |
| 期待効果 | 非充電ノードの消耗抑制。重複配送は発生しうるが冪等化で収束 |
| トレードオフ | サーバー不在時間帯は集約処理が停止 |
| 不採用案 | 全ノード動的選出（消費電力増）、固定単一サーバー（単一障害点）、exactly-once（複雑性過大） |
| 未確定事項 | heartbeat interval/timeout、high-water mark保持粒度、スターからメッシュ中継への移行条件 |
